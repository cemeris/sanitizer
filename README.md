# Sanitizer

Open-source browser app for sanitizing private data in markdown-based content before using cloud AI tools.

## Core direction

- Browser-only (no Node.js runtime required for app usage)
- Fully offline runtime (no CDN dependency)
- Markdown-first editing workflow
- Primary input is paste/import into markdown editor
- Optional `.docx` import via local `mammoth.js`
- Offline `.xlsx`, `.csv`, and `.tsv` import/export using browser-native APIs

## Run

Serve this folder with a static file server (required for loading the JSON name
database), then open `index.html` in a browser.

## Current prototype features

- IndexedDB project storage (multiple projects and files)
- Original/sanitized content separation per file
- Modal-based file import from a single button
- Multi-file support: `.md`, `.markdown`, `.txt`, `.html`, `.htm`, `.docx`, `.xlsx`, `.csv`, `.tsv`
- Markdown editor + live preview
- Variable creation from selected text (`{variable_name}`)
- Replace-all exact repetitions
- Restore placeholders one-by-one or all at once
- Project-scoped variables usable across all files
- Auto-detect sensitive data (emails, LV phone numbers, LV company prefixes)
- Auto-detects: IBAN, personal code, address, dates, registration numbers, vehicle plates, postal codes, URLs with query params
- Auto-detects configured Latvian first-name + surname pairs, including common case forms
- Person-name detection runs before other sensitive-data detectors and keeps an adjacent name + surname as one variable
- Detects markdown tables before sanitization and scans each cell independently, preserving table delimiters and escaped pipes
- Copy sanitized output
- Export sanitized markdown to `.docx` (basic formatting)
- Export sanitized Markdown tables to `.xlsx` with one worksheet per table/heading
- Autosave-only workflow (no manual Save button)
- Delete support for active project, active file, and variables

## Markdown quick hints

- `# Title` and `## Section` for headings
- `**bold**` and `*italic*`
- `- item` for bullet lists
- `[label](https://example.com)` for links
- `` `inline code` `` and fenced blocks with triple backticks
- `{client_name}` style placeholders for sanitized values
- Tables: `| Col | Col |` followed by `| --- | --- |`
- Alignment blocks:
  - `:::left` ... `:::`
  - `:::center` ... `:::`
  - `:::right` ... `:::`
- Variable shortcut: select text and press `Space` to create a variable (selection is trimmed)

The local person-name data is stored in `data/person-names/` as separate JSON
files for first names, surnames, and declension classes. Each name entry stores
only a stem (`root`) and a declension class; case endings are maintained once
in `declension-classes.json` and generated by `person-name-database.js`. Use
`overrides` only for irregular forms. No name data is sent to a server.

Refresh the public-source datasets with:

```bash
node scripts/import-person-name-data.js
```

The importer uses the PMLP first-name CSV and CSP surname CSV, then writes the
generated files to `data/person-names/`. CSP's public surname dataset only
includes surnames with a total above ten, so historical and rare surnames can
be added later as a separately attributed source.

## Testing

Run deterministic sanitizer engine tests:

```bash
node --test tests/sanitizer-core.test.js
```
